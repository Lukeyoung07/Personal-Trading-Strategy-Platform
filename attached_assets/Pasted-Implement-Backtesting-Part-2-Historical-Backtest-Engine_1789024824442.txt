==================================================
1. HISTORICAL MARKET DATA
==================================================

Use the existing Market Data Service and genuine historical OHLC candle data from the existing BiQuote integration.

Use the exact:

- Instrument
- Timeframe
- Start date
- End date

selected in the saved backtest configuration.

Do NOT create fake candles.

Do NOT fabricate prices.

Do NOT interpolate missing candles.

Do NOT duplicate candles.

Do NOT stretch candles.

Do NOT use placeholder data.

If sufficient historical data is unavailable, return a clear error.

Example:

"Insufficient historical data for XAUUSD 5m for the selected period."

Do not present an incomplete dataset as a complete backtest.

==================================================
2. EXACT STRATEGY VERSION
==================================================

Use the exact strategy version stored in the backtest configuration.

If the user selected:

Gold Strategy v3

the backtest MUST use v3.

Do NOT automatically use the latest version.

Do NOT substitute another version.

Do NOT copy the current strategy into a new version.

The completed backtest must retain the exact strategy version ID that was selected.

If the strategy is edited or a new version is created later, an existing backtest must remain associated with its original version.

==================================================
3. USE EXISTING STRATEGY LOGIC
==================================================

Reuse the existing strategy definition and evaluation logic wherever possible.

The backtest should respect the selected strategy version's existing:

- Conditions
- Entry rules
- Exit rules
- Stop-loss rules
- Take-profit rules
- Reset rules
- Risk settings

Do NOT create a second unrelated strategy system.

Do NOT invent generic entry/exit rules.

If a particular existing strategy condition cannot currently be evaluated using historical OHLC data, do NOT guess.

Return a clear explanation of the limitation instead.

==================================================
4. CHRONOLOGICAL EVALUATION
==================================================

Process historical candles strictly from oldest to newest.

For each candle:

1. Evaluate the strategy using only information available at that point.
2. Evaluate the strategy conditions.
3. Determine whether an entry signal occurs.
4. Manage any open simulated position.
5. Determine whether an exit occurs.
6. Record completed trades.
7. Continue to the next candle.

IMPORTANT:

Prevent look-ahead bias.

A future candle must NEVER influence a previous decision.

Do not use future prices.

Do not inspect the entire historical dataset when making an earlier trading decision.

==================================================
5. EXECUTION RULE
==================================================

Because the historical data is OHLC candle data rather than historical tick data, use a clearly defined execution convention.

Do not claim tick-level execution accuracy.

If a strategy produces a signal based on a completed candle, use a consistent execution method that does not use information that was unavailable at the time.

Store the execution convention with the backtest.

==================================================
6. SIMULATED TRADES
==================================================

When a valid historical entry occurs, create a simulated trade.

Record:

- Backtest ID
- Strategy ID
- Exact strategy version ID
- Instrument
- Timeframe
- Direction
- Entry timestamp
- Entry price
- Stop-loss when applicable
- Take-profit when applicable
- Exit timestamp
- Exit price
- Profit/loss
- Entry reason
- Exit reason

These trades are BACKTEST trades only.

Do NOT add them to the real Trade Journal.

==================================================
7. STOP LOSS / TAKE PROFIT
==================================================

If the selected strategy version contains stop-loss or take-profit rules, simulate them using the available historical OHLC data.

If both SL and TP could have been reached during the same candle and OHLC data cannot determine which happened first:

DO NOT guess.

Use a clearly defined conservative handling rule.

Document that limitation in the backtest assumptions.

==================================================
8. POSITION MANAGEMENT
==================================================

Correctly handle:

- No open position
- Open position
- Entry
- Exit
- Position direction
- Strategy reset conditions

Do not allow impossible overlapping positions if the existing strategy does not permit them.

Do not invent position-management behavior that does not exist in the strategy.

==================================================
9. ZERO TRADES
==================================================

If the strategy produces zero trades:

Do NOT treat this as an error.

Complete the backtest with:

"0 trades found for this strategy and period."

Save:

- Strategy
- Version
- Instrument
- Timeframe
- Date range
- Candles processed
- 0 trades
- Completion status

Do not fabricate performance statistics.

==================================================
10. BACKTEST STATUS
==================================================

The saved backtest should have a clear lifecycle such as:

- Pending
- Running
- Completed
- Failed

When the user clicks Run Backtest:

1. Create/use the backtest configuration.
2. Start the historical calculation.
3. Process the candles.
4. Save simulated trades.
5. Mark the backtest Completed.

If something fails, mark it Failed and store a useful error message.

Do not leave failed backtests appearing as completed.
