Fix the Build with AI concept-resolution pipeline so natural-language strategy instructions cannot be incorrectly converted into additional trading concepts or cause canonical executable concepts to become review-required.

This is a SYSTEM-LEVEL FIX, not a prompt-specific exception.

Use the canonical Trading Concept Library as the ONLY authority for whether something is a trading concept.

PROBLEM REPRODUCTION:

This legitimate request:

"Create a backtestable XAUUSD strategy using Liquidity Sweep and Displacement. The Liquidity Sweep must occur before Displacement. Use closed candles. Use 1% stop loss and 2% take profit."

incorrectly produced review-required items:

- Sell-Side Liquidity condition
- Support condition
- Buy-Side Liquidity condition
- Resistance condition
- Closed Candles
- Displacement
- Concept "Closed Candles" is not in the Trading Concept Library

This must be fixed generically.

REQUIRED BEHAVIOUR:

1. Canonical concept resolution

Every extracted concept must first be resolved against the canonical Trading Concept Library.

The AI must NOT treat ordinary trading vocabulary as a separate concept merely because it appears in a strategy description.

For example:

- "closed candles" = execution/data requirement, NOT a trading concept.
- "support level" inside a Liquidity Sweep definition = parameter/level source of Liquidity Sweep, NOT automatically a separate Support concept.
- "resistance level" inside a Liquidity Sweep definition = parameter/level source of Liquidity Sweep, NOT automatically a separate Resistance concept.
- "buy-side liquidity" inside a Liquidity Sweep definition = part of the Liquidity Sweep rule/parameterization, NOT automatically a separate Buy-Side Liquidity entry condition.
- "sell-side liquidity" inside a Liquidity Sweep definition = part of the Liquidity Sweep rule/parameterization, NOT automatically a separate Sell-Side Liquidity entry condition.

Do NOT create separate concepts unless the user explicitly requests them as standalone conditions.

2. Nested concept language

The system must distinguish between:

A) A concept explicitly requested as a strategy condition.

Example:
"Use Liquidity Sweep."

This creates one Liquidity Sweep condition.

B) Terms used to describe how that concept works.

Example:
"price sweeps sell-side liquidity and closes back above the level."

This remains part of the Liquidity Sweep definition/parameters.

It must NOT create:

- Sell-Side Liquidity
- Support
- another Liquidity condition

unless those are explicitly requested as independent strategy conditions.

3. Execution instructions are NOT concepts

Create a robust classification between:

- trading concepts
- concept parameters
- relationship operators
- execution/data requirements
- risk-management rules
- metadata/instructions

If the canonical registry says a concept is executable, Build with AI must not downgrade it to review_required simply because its natural-language explanation contains other trading vocabulary.

Do not create additional concepts from the words used to describe that relationship.

The system must distinguish:

"Liquidity Sweep followed by Displacement"

from:

"Liquidity Sweep AND Support AND Sell-Side Liquidity AND Displacement"

The first is what the user requested.
