==================================================
GOAL
==================================================

Add a simple, beginner-friendly Historical Backtesting feature.

The purpose is to let a user select an existing strategy version and see how that strategy would have performed using genuine historical market data.

The backtester should be easy to understand and require very little configuration.

The setup should feel like:

Choose Strategy
→ Choose Version
→ Choose Market
→ Choose Timeframe
→ Choose Period
→ Run Backtest

Do NOT make this a complicated professional trading terminal.

Keep advanced technical details behind the scenes.

==================================================
1. BACKTEST SETUP
==================================================

Create a Backtesting page.

The main setup should contain:

Strategy
[ Select Strategy ▼ ]

Version
[ Select Version ▼ ]

Instrument
[ Select Instrument ▼ ]

Timeframe
[ Select Timeframe ▼ ]

Period
[ Last 7 Days ]
[ Last 30 Days ]
[ Last 90 Days ]
[ Custom ]

[ RUN BACKTEST ]

Use dropdowns/searchable selectors consistent with the existing application.

Do not require the user to manually enter technical IDs.

Only show instruments and timeframes that are actually supported by the existing market-data system.

==================================================
2. QUICK DATE OPTIONS
==================================================

Provide simple presets:

- Last 7 Days
- Last 30 Days
- Last 90 Days
- Custom

If Custom is selected, show:

Start Date
End Date

Validate that:

- Start date is before end date
- The selected range is valid
- Historical data exists for the selected market/timeframe

Do not run a misleading partial backtest if sufficient historical data is unavailable.

==================================================
3. EXACT STRATEGY VERSION
==================================================

The user must select the exact strategy version.

Example:

Gold Strategy
v1
v2
v3

If the user selects v2, the backtest must use v2 exactly.

Do not automatically switch to the newest version.

The backtest must remain permanently associated with the exact strategy version used.

If v4 is created later, an existing v2 backtest must not change.

==================================================
4. REAL HISTORICAL DATA
==================================================

Use genuine historical OHLC candles from the existing Market Data Service / BiQuote data.

Do NOT:

- Fabricate candles
- Simulate historical prices
- Duplicate candles
- Stretch candles
- Fill missing data with invented values
- Use fake results

If sufficient historical data is unavailable, clearly tell the user.

Example:

"Insufficient historical data for XAUUSD 5m for this period."

Do not present incomplete results as a complete backtest.

==================================================
5. SIMPLE BACKTEST ENGINE
==================================================

Evaluate historical candles chronologically.

At each candle:

1. Only use information that would have been available at that point in time.
2. Evaluate the selected strategy version.
3. Apply its existing strategy conditions.
4. Determine entries according to the strategy.
5. Manage positions according to the strategy's existing rules.
6. Determine exits.
7. Record the simulated trade.
8. Continue through the historical period.

Do NOT use future candles to make decisions about earlier candles.

Do NOT introduce look-ahead bias.

Use the existing strategy definitions wherever possible rather than creating a completely separate strategy interpretation system.

==================================================
6. EXISTING STRATEGY RULES
==================================================

Reuse the existing strategy version's:

- Conditions
- Entry rules
- Exit rules
- Stop-loss rules
- Take-profit rules
- Reset rules
- Risk settings

Do NOT replace these with generic trading rules.

If an existing strategy cannot currently be evaluated historically because required information is unavailable, do not invent a solution.

Clearly explain the limitation.

==================================================
7. TRADE RESULTS
==================================================

- Strategy

- Instrument
- Timeframe
- Entry time
- Entry price
- Exit time
- Exit price
- Direction
- Stop-loss when applicable
- Take-profit when applicable
- Profit/loss
- Entry reason
- Exit reason

These are simulated backtest trades.

Do NOT add them to the user's real Trade Journal.

Keep the chart visually simple.

The chart should use the same general chart style already used elsewhere in the application.

This is a separate historical backtest chart.

==================================================

16. DATA QUALITY
==================================================

Validate:

- Exact strategy version
- Instrument
- Timeframe
- Date range

If data is missing or insufficient, explain the issue clearly.

==================================================
17. EXECUTION ASSUMPTIONS
==================================================

The backtest must clearly document how historical entries/exits are simulated.

Do not claim tick-level accuracy when only OHLC candle data is available.

If signals are evaluated on candle close, use a clearly defined execution convention that does not use information from the future.

Display a small "Backtest assumptions" section explaining the basic execution model.

Keep this information secondary so it does not clutter the main interface.

- Period
