“Historical data is not available for this market and timeframe during the selected period.”

We already have a working Dukascopy historical adapter and have verified that the official Dukascopy endpoints return genuine historical candles for:

- XAUUSD → Dukascopy XAU-USD
- USTEC → Dukascopy USATECH.IDX-USD

Verified timeframes:
- 5m, derived from genuine 1m candles
- 1h, retrieved from the official monthly historical endpoint

2. Make Dukascopy historical retrieval reliable

Implement robust sequential historical retrieval using the existing Dukascopy adapter.

Requirements:

- Never make large concurrent requests.
- Respect Dukascopy rate limits.
- Use throttling between requests.
- Retry HTTP 429 responses with exponential backoff.
- Retry transient network/server failures.
- Stop safely if the provider continues rate limiting.
- Handle monthly boundaries correctly.
- Handle newest-first and chronological responses correctly.
- Remove duplicate candles.
- Sort candles chronologically.
- Preserve genuine OHLCV values.
- Never fabricate missing candles.

The retrieval system must be able to request a bounded historical period rather than only the small recent windows currently being returned.

Use a unique key preventing duplicate candles.

If the same historical period is requested again, TradeX should use already stored candles rather than downloading the entire range again.

4. Backtest data retrieval

Before running a backtest:

- Determine every timeframe required by the strategy.
- Determine the exact requested start/end timestamps.
- Check the stored historical data for complete coverage.
- If coverage is incomplete, retrieve only the missing periods from Dukascopy.
- Store the newly retrieved candles.
- Re-check coverage.
- Only then start the backtest.

For multi-timeframe strategies:

- Load every required timeframe.
- Keep the smallest timeframe as the execution series.
- Keep higher/lower timeframe condition series separate.
- Preserve the existing closed-candle-only and no-lookahead behavior.

6. Important: distinguish unavailable data from retrieval failure

“Historical data is not available.”

“Historical data retrieval was rate-limited by Dukascopy. Please retry later.”

If the provider genuinely has no data for the requested period, report the actual available range.

If only part of the requested period was retrieved, the backtest MUST NOT run.
