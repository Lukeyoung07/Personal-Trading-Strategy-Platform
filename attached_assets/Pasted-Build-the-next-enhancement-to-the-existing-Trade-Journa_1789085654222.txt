==================================================
1. MAIN JOURNAL LAYOUT
==================================================

Create a clean, professional Journal experience.

The main Journal should have a simple hierarchy:

TRADE JOURNAL

Monthly summary
↓
Daily P/L calendar
↓
Selected-day details
↓
Monthly performance
↓
Existing trade list/history

Do not overcrowd the page.

The user should be able to understand their performance immediately without having to navigate through multiple complicated screens.

Use the existing application's design system.

Prioritise:

- Clean
- Modern
- Minimal
- Easy to navigate
- Clear typography
- Good spacing
- Strong visual hierarchy
- Responsive design
- Beginner friendly

Do not introduce unnecessary decorative UI.

==================================================
2. MONTHLY SUMMARY
==================================================

At the top of the Journal, show a compact monthly summary.

Include:

- Monthly P/L
- Total trades
- Win rate
- Best day

Where useful, also show:

- Worst day
- Average trading day

All values must be calculated from REAL persisted Journal trades.

Do not use mock data.

Do not include backtest trades in Journal statistics.

==================================================
3. DAILY P/L CALENDAR
==================================================

Make the calendar the main visual focus of the Journal.

Display the complete selected month.

Example:

September 2026

< Previous       September 2026       Next >

Calendar:

Monday | Tuesday | Wednesday | Thursday | Friday | Saturday | Sunday

Each day should show:

- Day number
- Daily P/L when trades exist

Example:

12
+£8.42

or:

13
-£3.17

Days without trades should remain clean and visually quiet.

Future days must not be presented as trading days with £0 performance.

Positive and negative performance must be easy to distinguish.

Do not rely solely on colour.

==================================================
4. MONTH NAVIGATION
==================================================

Allow the user to:

- Move to previous month
- Move to next month
- Return to the current month

Month navigation should be simple and obvious.

Do not reload the entire application unnecessarily when changing months.

The selected month should determine the calendar and monthly statistics.

==================================================
5. CLICKING A DAY
==================================================

When the user clicks a day containing trades, show a clean day-detail section.

Display:

- Full date
- Daily P/L
- Number of trades
- Winning trades
- Losing trades
- Win rate
- Average winner
- Average loser
- Best trade
- Worst trade

Then show the individual trades from that day.

Reuse the existing Journal trade display wherever possible.

Do not create duplicate trade data.

==================================================
6. DAILY NOTES
==================================================

Allow the user to optionally add a note to a specific trading day.

Example:

"Overtraded today and took two setups outside my strategy."

Daily notes are separate from individual trade notes.

The note must be persisted so it remains when the user returns to that date.

Do not automatically generate notes.

The user controls the content.

==================================================
7. MONTHLY PERFORMANCE CHART
==================================================

Add a clean monthly performance chart below the calendar.

Show cumulative Journal P/L throughout the selected month.

The chart should use the actual persisted Journal trades.

For example:

Day 1 → +£5
Day 2 → +£3
Day 3 → -£2

Cumulative:

Day 1 → +£5
Day 2 → +£8
Day 3 → +£6

Use a simple, readable line chart.

The chart should update automatically when:

- Month changes
- Journal trades change
- A trade is edited
- A trade is deleted where deletion is supported

Do not use backtest data.

Do not invent values.

==================================================
8. TRADING STREAKS
==================================================

Add a small performance section showing real trading-day streaks.

Include:

- Current winning/losing streak
- Best winning streak
- Best losing streak

Define a winning day as a day with positive realised Journal P/L.

Define a losing day as a day with negative realised Journal P/L.

A day with no trades should not count as a winning or losing day.

Clearly document/use consistent logic.

==================================================

==================================================

Show:

- Best trading day
- Worst trading day
- Average trading day

Use actual Journal data for the selected month.

v2 → 18 trades → 67% → +£87
