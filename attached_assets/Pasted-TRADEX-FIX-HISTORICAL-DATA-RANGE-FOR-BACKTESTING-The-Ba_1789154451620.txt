The Backtesting system has a historical-data problem.

When I select a longer backtest period, the Backtest result may only process a small number of recent candles instead of the complete requested historical range.

For example, selecting:

Last 90 Days

previously resulted in only:

289 × 5-minute candles
132 × 1-hour candles

This is far too little data for a genuine 90-day backtest.

Fix the underlying historical-data retrieval system so the date range selected by the user is actually respected throughout the entire backtesting pipeline.

This must be a GENERAL FIX.

Do NOT hard-code:

- XAUUSD
- Gold
- 90 days
- 5 minutes
- 1 hour
- Any particular strategy

The fix must work for EVERY instrument, timeframe, strategy and date range.

3. PROVIDER LIMITS / PAGINATION
==================================================

Investigate whether the historical-data provider has limits such as:

- maximum candles per request
- maximum date range per request
- pagination
- request limits
- timeframe-specific limits

If the provider limits the amount of historical data returned per request, implement safe pagination or chunked requests through the existing MarketDataService.

For example:

A 1-year 5-minute request may require many separate historical-data requests.

The system must:

1. Request the first chunk.
2. Request the next chunk.
3. Continue until the entire requested range has been retrieved.
4. Combine all candles.
5. Remove duplicates.
6. Sort chronologically.
7. Pass the complete series to the Backtest engine.

Do NOT silently stop after the first provider response.
