REQUIRED BEHAVIOR

2. Add real execution for two risk rule types that currently exist only as review_required placeholders:
   - `structural_stop` referencing a specific entry condition (e.g. the Liquidity Sweep in this strategy) — compute the stop price as the swept extreme's price at the time that condition triggered, optionally with a small configurable buffer for spread/slippage. Default buffer = 0 unless the user specifies one.
   - `structural_target` referencing a specific condition (e.g. a liquidity_level condition, or "the next external liquidity level in the trend direction" generally) — compute the target price as that condition's detected level price.
   
   Both must become status: executable once a valid reference is resolved, with a real evaluatorVersion, following the same pattern as other executable risk rules in the registry. If the reference can't be resolved (e.g. user says "beyond the sweep" but there's no Liquidity Sweep condition in the strategy), keep it review_required with an honest explanation — don't fall back to inventing a percentage.

3. `risk_reward_multiple` validation (e.g. "at least 1.5x") must be evaluated using the concrete computed stop/target distances at the time of each trade, not a static check. If a candidate trade doesn't meet the minimum R:R once the actual structural levels are known, the trade must be skipped/rejected, not entered and flagged after the fact.

4. Backtesting and monitoring must share this exact same structural-stop/target resolution logic — same evaluator, same computation, no second interpretation in either engine.
